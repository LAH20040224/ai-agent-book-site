    அத்தியாயம் 5 · Coding Agent மற்றும் குறியீடு உருவாக்கம்¶

    குறியீடு என்பது "புதிய கருவிகளை உருவாக்கக்கூடிய கருவி" ஆகும், பொது-நோக்க ஏஜெண்டின் மேல்-திறன் (meta-capability) ஆகும். உற்பத்தி-தர Coding Agent ஐ எடுத்துக்காட்டாகக் கொண்டு, இந்த மிகச் சக்திவாய்ந்த பொது-நோக்கக் கருவியின் முழுமையான செயலாக்கத்தைக் காட்டுகிறது.

    ← முக்கிய README க்குத் திரும்பு · 📖 அத்தியாய உரையைப் படி

    துணை திட்டங்கள்¶

    சோதனை Project Type Description
    5-1 code-for-math ✅ அதே மாதிரியை அதே போட்டிக் கணிதக் கணக்குகள் தொகுப்பில் "தூய சிந்தனைச் சங்கிலி" மற்றும் "குறியீடு-உதவி" என்ற இரண்டு முறைகளில் ஒப்பிடுகிறது: பிந்தைய முறையில், கணக்குகள் Python-ஆக (sympy/numpy/scipy) முறைப்படுத்தப்பட்டு, function calling மூலம் துணை-செயல்முறை மணல் பெட்டியில் இயக்கப்படுகின்றன; பிழைக்கு உட்பட்ட மனக்கணக்குக்குப் பதிலாகத் துல்லியமான கணக்கீடு பயன்படுத்தப்படுவதால், துல்லியத்தன்மை குறிப்பிடத்தக்க அளவில் அதிகமாக உள்ளது.
    5-2 code-for-logic ✅ "Knights and Knaves" தர்க்கப் புதிர்களைக் கட்டுப்பாடு திருப்திக் கணக்குகளாக (CSP) மாற்றுகிறது: ஏஜென்ட் python-constraint ஐப் பயன்படுத்தி மாறிகள் மற்றும் இரு-நிபந்தனைக் கட்டுப்பாடுகளை வரையறுத்துத் தீர்வியை அழைக்கிறது; ஒரு K&K புதிர்த் தொகுப்பில் தூய இயற்கை மொழிப் பகுத்தறிவு மற்றும் குறியீடு-உதவி என்ற இரு முறைகளின் துல்லியத்தன்மையை ஒப்பிடுகிறது.
    5-3 small-model-codified-rules ✅ τ-bench விமான வாடிக்கையாளர் சேவைச் சூழ்நிலையை அடிப்படையாகக் கொண்ட கட்டுப்பாட்டுச் சோதனை: சிக்கலான வணிகக் கொள்கைகளை (திருப்பிச் செலுத்தும் விதிகள்) இயற்கை மொழி வரியூட்டல்களிலிருந்து குறியீடு/கருவிகளுக்குள் நகர்த்திய பிறகு, சிறிய மாதிரியின் பணி வெற்றி விகிதமும் கொள்கை இசைவும் பெரிதும் உயர்ந்தன; கருவிக்குள் உள்ள குறியீடுச் சரிபார்ப்பு மாதிரியின் தவறான புரிதல்களை நிகழ்நேரத்தில் தடுக்கிறது.
    5-4 paper-to-ppt ✅ "PPT உருவாக்குதல்" என்பதைக் குறியீடு உருவாக்கக் கணக்காக மறுசீரமைக்கிறது: Proposer Slidev (Markdown+HTML) குறியீட்டை எழுதுகிறது, Reviewer ஒவ்வொரு பக்கத்தையும் உண்மையில் PNG-ஆக வழங்கி (render), Vision LLM மூலம் வடிவமைப்புப் பிரச்சினைகளைச் சரிபார்த்து, கட்டமைக்கப்பட்ட பின்னூட்டத்தின் அடிப்படையில் மீள்திருத்தம் செய்கிறது; இரட்டை ஏஜென்ட் பணிப்பிரிவு சூழலின் உச்ச அளவைக் குறிப்பிடத்தக்க வகையில் குறைக்கிறது.
    5-5 paper-to-video ✅ "ஆய்வுக்கட்டுரை → PPT" என்பதன் அடிப்படையில் ஒவ்வொரு ஸ்லைடுக்கும் பேச்சுவழக்கான விளக்க உரையை உருவாக்கி, TTS ஐ அழைத்துக் குரலைத் தொகுத்து, பின்னர் ffmpeg ஐப் பயன்படுத்தி ஒவ்வொரு பக்கத்தின் திரைப்பிடிப்பையும் அதன் ஒலியையும் பக்கம் தோறும் ஒத்திசைத்து, விவரிப்புடன் கூடிய ஒரு விளக்கக் காணொளியாக இணைக்கிறது.
    5-6 video-edit ✅ பயனர் ஒரு பல-காட்சிக் காணொளியையும் ஒரு இயற்கை மொழித் தேவையையும் தர, ஏஜென்ட் "இரு-படி Vision இருப்பிடக் கண்டறிதல்" (முதலில் தோராயமாகவும் பின்னர் நுணுக்கமாகவும் சட்டகங்களை எடுத்துப் படித்தல்) மூலம் இலக்குக் காட்சியின் நேர எல்லைகளைத் தீர்மானிக்கிறது; துண்டை வெட்டிய பிறகு Reviewer இறுதிக் காணொளியிலிருந்து முக்கியச் சட்டகங்களை எடுத்துச் சரிபார்க்கிறது, தரமில்லையென்றால் மீள்செய்கிறது.
    5-7 adaptive-log-parser ✅ சுயமாகப் பரிணமிக்கக்கூடிய ஒரு பதிவு பாகுபடுத்தல் அமைப்பு: பாகுபடுத்த முடியாத புதிய வடிவமைப்பை எதிர்கொள்ளும்போது பிழை எழுப்புவதற்குப் பதிலாக, தோல்வியுற்ற மாதிரியையும் பிழைச் செய்தியையும் குறியீடு உருவாக்க ஏஜென்டிடம் கொடுத்து parse செயல்பாட்டை உருவாக்கச் செய்கிறது; தானியங்குச் சோதனை வெற்றியடைந்த பிறகு, அதைச் சூடாகப் புதுப்பித்து (hot update) பாகுபடுத்தல் பொறியில் பதிவு செய்கிறது — முழுச் செயல்முறையிலும் மனிதத் தலையீடு தேவையில்லை.
    5-8 log-diagnosis ✅ கண்டறிதல் ஏஜென்ட் உண்மையான HTTP தடங்கள், கட்டமைப்பு ஆவணங்கள் மற்றும் PRD-களைப் படித்து, பின்னடைவுச் சோதனைகளை உருவாக்கி திருத்தத்திற்கு முன்பும் பின்பும் மீள்செயல்படுத்துகிறது; அதிகாரப்பூர்வ இயக்கம் GitHub MCP வழியாக உண்மையான Issue-ஐ உருவாக்கி சான்றுகளை இரகசியமற்ற வடிவில் சேமிக்கிறது.
    5-9 dynamic-form ✅ தகவல் முழுமையற்ற கோரிக்கையை எதிர்கொள்ளும்போது, ஏஜென்ட் ஒவ்வொன்றாக வினவாமல், படிநிலைத் தர்க்கம் (cascading logic) கொண்ட சுய-உள்ளடக்கிய HTML படிவத்தை மாறும் முறையில் உருவாக்கி, பயனர் ஒரே முறையில் முழுமைப்படுத்த அனுமதிக்கிறது; முன்னணி (frontend) படிவத்தை JSON-ஆகத் தொகுத்து ஏஜென்டிடம் திருப்பிக் கொடுத்துப் பணியைத் தொடர்கிறது.
    5-10 erp-agent ✅ சீன இயற்கை மொழி வினவல்களை SQL-ஆக மாற்றித் தரவுத்தளத்தில் இயக்கி, முடிவு அட்டவணையை நேரடியாகக் காட்டுகிறது; மையம் கலைப்பொருள் முறை (artifact pattern): LLM SQL கலைப்பொருளை மட்டுமே உருவாக்குகிறது, தரவைத் தானே நகர்த்துவதில்லை — இது token-ஐயும் மிச்சப்படுத்துகிறது, கைமுறைக் கணக்கீட்டுப் பிழைகளையும் தவிர்க்கிறது; பல்லாயிரக்கணக்கான வரிகள் கொண்ட முடிவுகளையும் நொடிகளில் திருப்பித் தர முடியும்.
    5-11 conversational-ui ✅ பயனர் இயற்கை மொழியில் UI தனிப்பயனாக்கத் தேவைகளை (நிறம்/எழுத்துரு/உரை/வடிவமைப்பு) முன்வைக்க, ஏஜென்ட் தன்னாட்சியுடன் React முன்னணி மூலக் குறியீட்டைக் கண்டறிந்து மாற்றுகிறது; Vite-இன் சூடான ஏற்றம் (HMR) மூலம் மாற்றங்கள் உடனடியாக அமலுக்கு வருகின்றன; பல-சுற்று மீள் தனிப்பயனாக்கத்தை ஆதரிக்கிறது.
    5-12 agent-creator ✅ சரிபார்க்கப்பட்ட மாதிரி Agent-ஐ நகலெடுத்து மாற்றுவதையும் புதிதாக உருவாக்குவதையும் ஒப்பிடும் மெட்டாபுரோகிராமிங் Agent; இரு வழிகளும் compile, test மற்றும் உண்மையான Kimi K3 tool-calling API மூலம் சரிபார்க்கப்படுகின்றன.
