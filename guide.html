零基础也能学透 AI Agent：全书名词通关指南

写给不会编程的你：这份指南把《深入理解 AI Agent：设计原理与工程实践》（李博杰，开源书）里出现的名词，全部翻译成大白话。先读这份指南建立地图，再读原书正文，遇到任何生词回来查。

原书在线阅读：学习网站（见配套部署说明）或 https://bojieli.github.io/ai-agent-book/

第一部分：不会编程，到底怎么学这本书？

这本书在讲什么（一句话）

教你设计一个"会自己干活的 AI"：不是你问一句它答一句的聊天机器人，而是你交代一个任务（比如"帮我把这个月的销售数据整理成报表并发给老板"），它能自己拆解步骤、查资料、操作软件、发现错误并改正，直到把活干完。

不会编程，能学到什么？

这本书的内容分三层：

层次 内容 不会编程能学吗
思想层 为什么这么设计？每个决策背后的取舍 ✅ 完全能学，这是全书最值钱的部分
架构层 各个部件怎么配合、信息怎么流动 ✅ 能学，靠类比就能理解
代码层 94 个配套实验，要动手跑 Python ⚠️ 可以跳过，或借助 AI 编程工具代劳

核心结论：跳过所有代码块，你依然能学透这本书的 80%——而且是作者最看重的 80%（作者原话：本书的核心价值在于"架构设计原则和工程实践的方法论"，而非具体算法）。

学习的三把钥匙

钥匙一：记住一个总公式

Agent = LLM + 上下文 + 工具

全书十章都是这个公式的展开。任何一个新名词，先问一句："它属于大脑、眼睛，还是手脚？还是让这三者配合得更好的东西？"——能回答这个问题，这个名词你就懂了一半。

钥匙二：用类比代替定义

书里的每个技术名词，本质都在描述一个你熟悉的人类世界的东西：公司岗位、笔记本、工具箱、考试、带徒弟……本指南的全部工作就是给你这些类比。

钥匙三：顺着"一个 Agent 的一生"这条主线读

  • 第 1 章：Agent 是什么（出生证明）
  • 第 2~5 章：怎么造一个 Agent（成长）
  • 第 6 章：怎么考一个 Agent（考试）
  • 第 7~8 章：Agent 怎么变强（进修）
  • 第 9~10 章：Agent 怎么用五官、怎么组团（社会化）

全书最重要的一个"术语约定"（先看这个，不然会混乱）

中文里"推理"一词被太多人混用，作者特意做了区分，读书时必须记住：

  • 思考（reasoning）= 模型"想"的过程。就像学生考试时在草稿纸上写演算步骤。
  • 推理（inference）= 模型"运行"这件事本身。就像"这台机器开机运转了"。

所以书里说"思考模型"指的是会先打草稿再回答的模型（如 DeepSeek-R1、OpenAI o 系列）；说"推理成本"指的是"让模型跑起来要花多少钱"。

第二部分：打地基——8 个绕不开的基础名词

在进章节之前，先扫清这些贯穿全书的基础词。

1. AI Agent（智能体）

大白话：能自己感知情况、自己做决定、自己动手完成任务的 AI 系统。 类比：普通聊天 AI 像"电话咨询顾问"——只动嘴；Agent 像"全能行政助理"——听完任务会去查邮件、填表格、打电话，把事办完。 注意：判断一个系统是不是 Agent，就看它有没有"眼睛"（能看信息）和"手脚"（能做事情），而不只是会聊天。

2. LLM（Large Language Model，大语言模型）

大白话：用海量文字训练出来的超大 AI 模型，是 Agent 的"大脑"。ChatGPT、Claude、DeepSeek、Kimi 背后都是它。 类比：一个读完了整个图书馆、记性极好、文笔极佳，但没有眼睛耳朵、没有手脚、对今天发生的事一无所知的天才。它的特长是"根据上文猜下文"。 书中定位：公式里的第一项，Agent 的决策核心。

3. Token（词元）

大白话：模型读写文字的最小单位。一个汉字、半个英文单词、一个标点都可能是一个 Token。 类比：模型的"粮食"和"字数计费单位"。模型的记忆容量（上下文长度）和 API 收费都按 Token 算。 为什么重要：书里说的"上下文窗口 100 万 Token"≈ 大脑一次能摊开在桌面上的资料总量；"思考 Token"≈ 草稿纸的长度。

4. Prompt（提示词）与 System Prompt（系统提示词）

大白话：Prompt 就是你发给模型的话。System Prompt 是开发者预先写好、全程不变的"隐形指令"，用户看不到。 类比：System Prompt 是员工的岗位说明书——"你是客服，语气要礼貌，绝不承诺退款超过 500 元"。Prompt 是用户当下说的具体事。 书中定位：写好系统提示词的学问叫"提示工程"（第 2 章）。

5. 上下文（Context）

大白话：模型在做出每一个决定前，能看到的全部信息。 类比：开会时摊在桌上的所有资料——任务说明（系统提示词）、可用工具清单（工具定义）、之前的会议纪要（对话历史）、刚收到的传真（工具执行结果）。桌上没有的，模型一律不知道。 书中金句：上下文决定 Agent 能力上限——"给模型看什么、怎么组织，比模型本身有多聪明更影响结果"。 记住一个数字 5：书里把上下文拆成 5 个组成部分——①系统提示词 ②工具定义（这两样是固定的"静态前缀"）③用户消息 ④模型回复 ⑤工具执行结果（这三样是不断变长的"动态轨迹"）。

6. 工具（Tools）

大白话：模型可以调用的外部能力——搜索网页、查数据库、发邮件、操作软件、执行代码。 类比：Agent 的"手脚"。没有工具的模型只会说，有了工具才会做。 书中定位：公式第三项。第 4 章专门讲怎么设计工具，第 5 章讲"代码"这件最强的工具。

7. API（应用程序接口）

大白话：程序之间互相说话的"标准插座"。你的程序通过 API 调用大模型，大模型通过 API 使用工具。 类比：餐厅的点餐窗口——你不需要进厨房，按格式递单子（请求），厨房按格式出菜（响应）。 零基础知识量：知道"调用 API"="按标准格式发请求拿结果"就够了，第 2 章的代码示例可以直接跳过。

8. 参数（Parameters / Weights，权重）

大白话：模型"大脑"内部的神经元连接强度，训练时学到的一切知识都刻在里面。一个模型有几百亿个参数。 类比：大脑的神经回路。改参数 = 给大脑做"物理改造"；不改参数只靠提示词 = 给大脑"下口头指示"。 为什么重要：第 7 章"模型后训练"讲的就是怎么改参数；第 8 章会告诉你"改参数"只是让 Agent 变强的四种方式之一。

第三部分：十章名词地图

每一章的结构：本章讲什么 → 核心名词逐个翻译 → 一句话记住本章。

第 1 章 · Agent 基础知识：一个 Agent 是怎么运转的

本章讲什么：建立全书框架——核心公式，以及 Agent 干活的循环方式。

名词 大白话解释
观察空间 / 动作空间（Observation / Action Space） 学术版说法。"观察空间"= Agent 能看到什么的范围（眼睛可视范围）；"动作空间"= Agent 能做什么动作的范围（手脚可动范围）。扩大这两个空间，就能让原本做不了的任务变得能做。
ReAct 循环 Agent 干活的基本节奏：思考 → 行动 → 观察 → 再思考 → …… 像修车师傅：想想哪坏了（思考）→ 拧一下螺丝（行动）→ 看看还漏不漏油（观察）→ 再想下一步。
轨迹（Trajectory） Agent 一轮轮"思考、行动、观察"留下的完整记录。像飞机的黑匣子，出事后回放轨迹就能知道哪一步错了。
Harness（工程） 本书的核心概念之一。直译是"马具/挽具"——套在模型外面、让它可靠干活的一整套工程装置。大脑再聪明也会犯错，Harness 负责约束它、验证它、纠正它。作者观点：模型能力大家都能买到，Harness 才是真正的竞争力。
Harness 的五个功能 上下文（给够信息）、工具（接口清晰）、约束（不该做的默认禁止，像手机 App 权限）、验证（检查结果对不对）、纠正（错了能恢复）。五环构成可靠性闭环。
ACI（Agent-Computer Interface） "给 Agent 用的操作界面"设计学。原则：从 Agent 视角而不是程序员视角设计工具接口，像 SIM 卡缺角一样"防呆"——让错误从设计上就不可能发生。
编排模式（Orchestration） 多个 AI 步骤怎么串联的组织方式。书里讲五种：链式（流水线，一道接一道）、路由（分诊台，看情况转给不同专科）、并行（多人同时做再汇总）、编排者-工人（项目经理派活）、评估者-优化者（写手 + 编辑来回改稿）。
工作流 vs 自主 Agent 工作流 = 固定流水线，每一步人事先排好，稳但不灵活；自主 Agent = 只给目标，路线让它自己定，灵活但难控制。作者建议：先优化提示词 → 再上工作流 → 最后才考虑自主 Agent。
护栏（Guardrails） 防止 Agent 闯祸的安全栏杆：金额上限、敏感操作要人批准、危险指令直接拦截。
对齐（Alignment） 让 AI 的行为和人类的真实意图保持一致——不只照字面办事，还要办"你真正想要的事"。
消融实验（Ablation Study） "逐个拆零件看影响"的实验法：把系统提示词删掉看会怎样，把历史记录删掉看会怎样……以此证明每个部件都不可或缺。第 6 章的评估方法论就靠它。
Artifact（产物） Agent 干活时产出的文件：写好的文档、生成的表格、画好的图。区别于"聊天里说的话"，产物是留下来能用的东西。

一句话记住第 1 章：Agent = 大脑 + 眼睛 + 手脚，靠"思考→行动→观察"循环干活，靠 Harness 保证可靠。

第 2 章 · 上下文工程：给大脑看什么，是门大学问

本章讲什么：全书最关键一章。模型的"桌面"就那么大，放什么、怎么摆、摆不下怎么办。

名词 大白话解释
上下文工程（Context Engineering） 精心设计"模型每次做决定时能看到什么"的工程学问。类比：给决策者准备简报的艺术——信息不全他判断失误，塞太多他抓不住重点。
消息四种角色（system / user / assistant / tool） API 里的四种"发言人"：system=岗位说明书（开发者的规矩）、user=用户说的话、assistant=模型的回复、tool=工具交回来的结果。四者加工具定义，正好对应第一章的上下文五部分。
Chat Template（聊天模板） 把"谁说了什么"翻译成模型能读懂的内部格式。类比：会议记录的统一模板——【主持人】【发言人】【决议】各归各位，模型才分得清哪句是谁说的。
KV Cache 模型的"草稿复用"技术：算过的内容存起来，下次接着写不用从头重算。代价：一旦改动了前面的内容，后面存的所有草稿全部作废。所以它约束你：上下文要"只往后加，别改前面"。
Prompt Cache（提示缓存） KV Cache 的"持久版"：把常用前缀（比如很长的岗位说明书）的运算结果存在服务商那里，下次直接复用，又快又便宜。
提示工程（Prompt Engineering） 打磨系统提示词的学问：语气人格、结构格式、流程设计、业务规则细化。类比：给新员工写岗位手册——写得越具体、越有流程，他干活越稳。
Few-shot 示例 在提示词里给模型看几个"标准答案样例"，让它照着做。给 3 个例子 = 3-shot；一个不给 = Zero-shot。类比：培训时先给看三份优秀报告模板。
提示注入（Prompt Injection） Agent 时代的"网络诈骗"：坏人把恶意指令藏在网页/邮件里，Agent 读到后可能被"洗脑"，做出越权操作（比如把数据发给别人）。第 2 章讲攻击原理，第 4 章讲防御。
Agent Skills（技能） 把"某类任务的专业知识"打包成可插拔的技能包，用到时才加载，不常驻大脑。类比：员工的"业务手册书架"——平时不在桌上，遇到对应业务才取下来翻。解决的是"提示词无限膨胀"问题。
Agent 状态栏 在上下文里给模型放一块"仪表盘"：现在几点、任务进行到哪步、用户什么状态。类比：汽车仪表盘——不看仪表盘开车，会错过油量和时速。
上下文压缩（Context Compression） 对话太长装不下时，把前面的内容提炼成摘要，用摘要替换原文。类比：会议纪要——3 小时的会，新人看 2 页纪要就能接上。
上下文腐化（Context Rot / Degradation） 上下文越堆越长，里面过时、矛盾、无关的信息越来越多，模型表现反而下降。类比：办公桌上文件堆成山，重要的那张反而找不到了。
子 Agent 上下文隔离 大任务拆给"子 Agent"单独干，它有自己的独立桌面，干完只把结论交回来。类比：老板不需要看外包团队的所有过程文件，只看最终交付——主桌面保持干净。隔离优于压缩是书里的重要原则。

一句话记住第 2 章：上下文是 Agent 的眼睛；桌面管理（放什么、复用什么、何时清理）决定它能看多远、看多清。

第 3 章 · 用户记忆和知识库：让 Agent 跨对话记住你

本章讲什么：第 2 章管"一次对话内"的信息，本章管"跨对话"的持久记忆和外部知识。

名词 大白话解释
用户记忆（User Memory） Agent 跨多次对话记住的关于你的信息：你的偏好、习惯、历史。类比：老管家记得"先生喝咖啡不加糖"。
记忆的四种存储格式 书中四种由简到繁的记法：Simple Notes（便利贴，一条一条事实）、JSON Cards（档案卡片，分门别类带结构）等。越简单越好维护，越复杂表达力越强——取舍是本章主题。
记忆压缩与整理 定期把零碎记忆归纳合并，去掉重复和过时的。类比：年底整理档案柜。
日志脱敏 记录日志时自动抹掉密码、身份证号等敏感信息。类比：病历公开前把病人姓名涂黑。
RAG（Retrieval-Augmented Generation，检索增强生成） 全书最高频术语之一。模型回答前，先从资料库里检索相关内容，摆在桌上，再回答。类比：开卷考试——不用把整本书背下来，会查就行。解决两大问题：模型不知道你的私有资料；模型知识有截止日期。
分块（Chunking） 把长文档切成小段作为检索单位。切太大找不准，切太小没上下文——像把书撕成合适的卡片。
嵌入（Embedding） 把文字变成一串数字（向量），让"意思相近"的文字在数字空间里也离得近。类比：给每段文字一个"语义 GPS 坐标"，搜"开心"也能找到"喜悦"。
稠密嵌入 / 稀疏嵌入 两种找资料的方式：稠密=按意思找（搜"肚子疼"能找到"胃胀气"）；稀疏=按关键词找（搜"BM25"只找含这三个字母的）。
混合检索 意思找 + 关键词找，两路结果合并。像导航既看"语义目的地"又看"精确门牌号"。
重排序（Rerank） 粗选出 100 条候选后，再用更精细的模型排出最相关的前几条。类比：海选之后还有复赛评委打分。
recall@k 检索质量的度量：正确答案出现在前 k 条结果里的比例。考试"前 5 名里有你孩子"的概率。
RAPTOR 给文档建"目录树"的检索法：小块→摘要→摘要的摘要，一层层组织。类比：公司的组织架构——员工→部门→事业部，问宏观问题找高层节点，问细节找叶子。
GraphRAG / 知识图谱（Knowledge Graph） 把知识整理成"实体 + 关系"的网：张三—任职于—某公司—位于—某城市。类比：人物关系图谱，查"某人的老板的邻居"这种多跳问题特别强。
上下文感知检索（Contextual Retrieval） 给每个文档小块补上"它属于哪、在讲什么"的背景说明再检索，避免断章取义。类比：档案卡片上注明"出自第 3 章第 2 节"。
Agentic RAG（智能体化 RAG） 让 Agent 自己决定要不要查、查什么、查得够不够，不够再换个查法。从"固定开卷考试"升级为"研究员式的主动调研"。
双层记忆架构 本章压轴设计：档案卡片常驻桌面当"概览"，细节按需检索。类比：大脑记索引，细节查图书馆。

一句话记住第 3 章：记忆让 Agent 认识你，RAG 让 Agent 认识世界；检索质量决定回答质量。

第 4 章 · 工具：Agent 的手脚怎么造

本章讲什么：工具怎么设计、怎么标准化、怎么保证安全，以及 Agent 怎么从"随叫随到"变成"主动干活"。

名词 大白话解释
MCP（Model Context Protocol） 工具界的"USB-C 标准"：不管什么工具，按统一接口做，任何 Agent 都能即插即用。由 Anthropic 提出，已成行业事实标准。
感知工具 让 Agent 获取信息的工具：搜索、读文件、看网页——五官的延伸。只读不改，所以天然安全、可缓存。
执行工具 让 Agent 改变世界的工具：发邮件、下单、删文件——真正的"手"。最危险，需要层层防护。
协作工具 让 Agent 能创建"子 Agent"、给别的 Agent 派活和通信的工具。
提议者-审核者（Proposer-Reviewer） 重要操作双人复核：一个模块提议"我要删这个文件"，另一个独立模块审核"理由成立吗"，通过才执行。类比：大额转账要主管复核。
Sidecar（边车）机制 挂在 Agent 旁边的独立小助手，走单独通道查询/验证信息，不污染主上下文。类比：飞行员旁边的副驾驶，独立核对仪表。
事件驱动 / 异步 Agent 传统 Agent 像电话客服——你不打过去它永远等着；异步 Agent 像值班医生—— BP 机一响（事件来了：新邮件、定时点、股价异动）就主动开工。
Webhook "有事请呼这个地址"的通知机制：外部系统出事后，自动给指定网址发消息。类比：快递柜的取件短信。
Hooks / Cron / Heartbeat 让 Agent 自动行动的三种内置机制：Hooks=某个动作完成时顺带触发；Cron=定时闹钟（每天早上 8 点巡检）；Heartbeat=定期心跳自检（每隔一阵看看自己有没有待办）。
Channel（通道） 书里 PineClaw 的设计：给外部事件源（邮件、API 回调）开的专用入口，让第三方事件能即时唤醒 Agent。
虚拟身份与隔离执行环境 给 Agent 独立的账号、邮箱和"单间办公室"干活，既能以"它"的名义对外沟通，又把风险关在单间里。
主动工具发现 工具成百上千时，不把所有工具说明都堆在桌面（占地方还干扰判断），而是让 Agent 按需"查工具目录"找到该用哪个。类比：员工不需要背下全公司通讯录，会用 OA 查就行。
工具描述投毒 / 工具遮蔽 接入第三方工具的新风险：坏人在工具说明书里夹带私货（投毒），或恶意工具抢注相似名字冒充正规工具（遮蔽）。接入前要审查。

一句话记住第 4 章：工具设计决定能力上限，安全机制决定能不能上线，事件驱动让 Agent 从"应答机"变成"值班员"。

第 5 章 · Coding Agent 与代码生成：代码是 Agent 的"元能力"

本章讲什么：为什么"会写代码的 Agent + 一个文件系统"几乎是所有通用 Agent 的内核。（本章代码最多，不会编程就读论证和结论。）

名词 大白话解释
Coding Agent 会写代码、调 bug、跑测试的 Agent，如 Claude Code、Cursor。书里的关键洞察：它成熟不是因为代码模型特别强，而是因为软件行业几十年攒下了测试、版本管理等"现成验收体系"——天然就是最好的 Harness。
Sessionless（无会话）设计 不依赖"一直聊着的会话"，每个任务都能从保存的轨迹重新加载继续。类比：流水线工人换班——交接记录写清楚，谁来都能接着干。
代码是"元能力" 元能力 = 能创造其他能力的能力。代码是"能创造新工具的工具"：没有现成工具？Agent 现场写一个。
代码作为思考工具 心算不如笔算：模型概率性的"想"容易错，写成代码执行就是精确的。类比：口算三位数乘法容易错，列竖式就稳了。
代码作为业务规则的约束 把"退款不得超过 500 元"写成代码关卡，比写在提示词里可靠一万倍——提示词模型可能"忘"，代码不会通融。不可逆操作前的确定性防线。
生成式 UI（Generative UI） Agent 现场给你画界面：需要填表就生成表单，需要看趋势就生成图表。突破纯文字聊天的限制。
Agent 自举（Bootstrap） 终极形态：Agent 用代码修复和创造新的 Agent——"程序员写出了另一个程序员"。

一句话记住第 5 章：代码既是干活的手段，也是思考的工具、安全的闸门、创造新 Agent 的种子。

第 6 章 · Agent 的评估：怎么证明它真的变好了

本章讲什么：作者反复强调"没有评估，就没有进步"。本章讲怎么科学地给 Agent 考试。

名词 大白话解释
评估（Evaluation / Eval） 给 Agent 出的标准化考试：固定题目、固定评分、可重复。靠"感觉好像变好了"做改进是炼金术，靠评估才是科学。
Benchmark（基准测试） 公开的"统考卷子"，不同 Agent/模型做同一套题比谁分高。如测编程的 SWE-bench、测操作电脑的 OSWorld。
评估环境 考试的"考场"：让 Agent 在受控环境里真刀真枪操作，并自动记录对错。分两种：工具调用型（给它 API 让它完成任务）和人机交互型（模拟真人跟它对话周旋）。
任务数据集 考题库。设计讲究：描述要精确、难度要分层、对错要能客观验证、还要防"泄题"（题目混进训练数据）。
LLM-as-a-Judge 让另一个大模型当阅卷老师。因为 Agent 的很多产出（一段话、一通电话）没有标准答案，只能让"AI 老师"按评分标准判。
Rubric（评分细则） 给 AI 阅卷老师的打分标准："语气礼貌 20 分、信息完整 40 分、解决问题 40 分"。细则越细，判分越稳。
配对比较（Pairwise Comparison） 不看绝对分，让两份答卷摆一起比"哪份更好"，再汇总成排名。类比：选秀节目两两 PK。
统计显著性 防止"瞎猫碰上死耗子"：A 比 B 高 2 分，是真强还是运气好？题目量够不够、分差稳不稳，要用统计方法验证。
可观测性（Observability） 给运行中的 Agent 装"监控摄像头"：每一步调用、耗时、花费都有迹可查，出问题能回放定位。
A/B 测试 两组用户，一组用旧版一组用新版，看哪组指标好。互联网产品经典方法，Agent 迭代同样适用。
特性开关（Feature Flag） 新功能做成可远程开关的电闸：上线出问题不用改代码，直接把闸拉了。
仿真环境 给 Agent 造的"模拟训练场"（仿真的电商网站、仿真的电话对端），既能当考场，也能当第 7 章强化学习的练习场。领域随机化= 刻意把训练场条件做得五花八门，逼它学会应对真实世界的多样性。

一句话记住第 6 章：观察 → 假设 → 实验 → 验证，评估闭环让 Agent 工程从玄学变科学。

第 7 章 · 模型后训练：给大脑本身做升级

本章讲什么：全书技术含量最高的一章，讲怎么把能力"刻进"模型参数。（不会编程：掌握三阶段和 SFT/RL 的取舍即可，公式全可跳过。）

名词 大白话解释
预训练（Pre-training） 造大脑的"九年义务教育"：喂海量文本练"预测下一个词"，学会语言和常识。成本巨大，只有大厂做。
后训练（Post-training） 义务教育之后的"岗前培训"：让通用大脑学会听指令、用工具、按规矩办事。本章主角。
SFT（Supervised Fine-Tuning，监督微调） "照着范例学"：给模型看成千上万条"标准问 + 标准答"，教它照样学样。类比：新人培训期抄老师傅的话术。特点：长于记忆，先把输出格式稳定下来。
RL（Reinforcement Learning，强化学习） "在试错中学"：模型自己做事，做对了给奖励、做错了没奖励，慢慢摸索出好策略。类比：销售在实战中成长——成了有提成，败了总结教训。特点：长于泛化，能应对没见过的情况。
先 SFT 后 RL 铁律：先用 SFT 把格式和规范教会（不然奖励都算不出来），再用 RL 练应变。书里"SFT 记忆、RL 泛化"是全章最重要的一句话。
奖励模型 / RLHF RLHF = 基于人类反馈的强化学习：人标注"哪个回答更好"，训出一个奖励模型（AI 裁判），再用它给模型的表现自动打分发奖励。
RLVR 用"可验证的结果"发奖励：代码跑通了、数学算对了——对错有客观标准，不需要 AI 裁判。Coding、数学领域因此突飞猛进。
信用分配（Credit Assignment） 多轮任务的经典难题：谈了一个月终于签单，功劳算给哪一步？类比：球队赢了球，功劳怎么分给每个球员每次触球。
过程奖励 vs 结果奖励 只看结局（结果奖励）信号太稀疏，但逐步骤打分（过程奖励）又容易误判；书里的答案：奖励结果，约束过程。
RLVP（验证路径惩罚） 作者团队的方法：结局好给奖励，但过程中走了违规弯路要扣分——防止"结果对了就纵容手段"。
Reward Hacking（奖励黑客） 模型钻奖励规则的空子：让它"测通代码"，它把难测的用例删了。类比：按论文数发奖金，有人就拆香肠式灌水。设计奖励时必须防。
PPO / GRPO / DPO 主流强化学习算法的名字。零基础只需知道：它们是"发奖励学经验"的不同具体算法，书里强调数据和环境比选哪个算法更重要。
样本效率 学一次能长多少本事。样本效率低 = 要摔一万次才学会；当前 RL 的最大瓶颈。
On-Policy Distillation（在线策略蒸馏） 让"老师模型"对自己正在做的题逐字逐句指导，把稠密信号带进学习。类比：师傅站在旁边看你实操，每个动作都点评，而不是只看月底业绩。
LoRA 低成本微调技术：不动整个大脑，只训练一小块"外挂插件"。类比：不动地基，只改软装。
泛化 vs 记忆 记忆 = 背下见过的题；泛化 = 没见过的题也会做。SFT 偏前者，RL 偏后者——这是选技术路线的根本依据。

一句话记住第 7 章：SFT 教规矩、RL 练应变；环境和数据的质量，比算法的选择更能决定成败。

第 8 章 · Agent 的持续进化：让它越干越聪明

本章讲什么：模型公司不帮你升级大脑时，怎么让运行中的 Agent 自己积累经验、持续变强。

名词 大白话解释
持续进化 / 持续学习 Agent 从每天干活的成败中提取经验，变成自己的能力，像员工"在复盘中成长"。
学习信号 从一次任务里提炼出的"哪好哪不好"的依据：环境给的结果、过程是否违规、AI 评委的打分。
四种更新载体 学到的经验写去哪里？①知识（更新知识库——记在笔记本上）②指令（更新提示词/Skills——改进岗位手册）③程序（更新工具和 Harness——升级装备）④参数（更新模型本身——改造大脑）。越往后越根本，也越危险。
上下文适应 只在当前对话里"临时变聪明"——对话一关就忘。所以靠它不能实现真正的持续学习。
灰度发布 新版本先给一小撮场景用，没问题再全量。类比：新药先小范围临床试验。
回滚 新版出问题，一键退回旧版。进化的每一步都要留退路。
睡眠学习 像人睡觉时大脑整理白天记忆：Agent 在空闲时段批量整理经验、合并知识、淘汰过时内容。
可验证闭环 "发现问题 → 生成候选改进 → 验证 → 发布 → 继续观察"的完整回路。闭环里最要紧的是"验证"——没验证过的改动不许上线。

一句话记住第 8 章：在线干活攒证据，离线学习做改进，验证发布有退路——进化是个治理问题，不只是技术问题。

第 9 章 · 多模态与实时交互：给 Agent 装上嘴、眼和手

本章讲什么：Agent 走出文字世界——能打电话（语音）、能操作电脑（GUI）、能控制机器人（物理世界）。

名词 大白话解释
多模态（Multimodal） 能处理文字之外的信息：语音、图片、视频、动作。"模态"= 信息的形态。
级联流水线（Cascading） 语音方案一：耳朵（语音识别 ASR）→ 大脑（LLM）→ 嘴（语音合成 TTS）三段串联。像同传箱子里的接力。结构简单，但慢、且语气等副语言信息会丢失。
端到端 Omni 模型 语音方案二：一个模型直接"听声音进、出声音"。像真人口译，反应快、懂语气，但更难训练和控制。
全双工（Full-Duplex） 电话术语：双方可以同时说话、互相打断。半双工像对讲机（"over"才能换人说），全双工才是真对话。
VAD / ASR / TTS 语音三件套：VAD=检测"人开始/停止说话"；ASR=语音转文字（耳朵）；TTS=文字转语音（嘴）。
TTFT（首 Token 延迟） 你问完到它"开口第一个字"的等待时间。语音 Agent 体验的生命线——等 5 秒才接话，没人受得了。
快思考 / 慢思考 实时交互的两难：接话要快（快思考，凭直觉），答难题要深想（慢思考，打草稿）。书里讲三种架构：先应付再补答、先交互再提醒、边想边说统一模型。
Computer Use 让 Agent 像人一样操作图形界面：看屏幕截图 → 动鼠标键盘。好处是不挑软件（没有 API 的老软件也能用），坏处是慢且容易点错。
Grounding（视觉定位） "把'登录按钮'这个词对应到屏幕上的具体像素坐标"。Computer Use 的核心技术——看不懂按钮在哪，一切免谈。
VLM（视觉-语言模型） 能看图的 LLM，是 Computer Use 和机器人的眼睛。
OSWorld 测"操作电脑能力"的基准考试。书里数据：准确率已接近人类，但步骤数远超人类——会做，但笨。
VLA（Vision-Language-Action，视觉-语言-动作模型） 机器人的小脑：看着摄像头画面，听懂指令，直接输出关节动作。让机械臂"看到苹果 → 伸手抓住"。
Sim2Real 在仿真器里练好机器人，再迁移到真实世界。难点：仿真和真实总有差距（摩擦、光照、材质），这个差距叫"现实鸿沟"。
具身智能（Embodied AI） 有身体（机器人）的 AI，能在物理世界感知和行动。

一句话记住第 9 章：从文字到语音到 GUI 到机器人，共同的两大坎是"实时性"和"多模态"。

第 10 章 · 多 Agent 协作：从单打独斗到 Agent 社会

本章讲什么：多个 Agent 怎么分工、怎么通信、什么时候协作真的比单干强，以及海量 Agent 聚集后涌现的"社会"。

名词 大白话解释
上下文共享 vs 隔离 多 Agent 的第一设计维度：共享=大家看同一块桌面，信息零损耗但桌面挤爆；隔离=各有各的桌面，靠"移交包"传结论。类比：全组共享一个文档 vs 各写各的周报。
协作拓扑 第二设计维度，三种结构：对等模式（几个 Agent 平等互评，像写作小组互改稿）、管理者模式（一个项目经理派活，它的能力就是全队的瓶颈——要用最强模型）、去中心化模式（任务在 Agent 间流转，像工单系统）。
移交（Handoff） 一个 Agent 把任务连同情报转交给另一个。移交时信息怎么打包（全量移交 vs 提炼摘要）是大学问。
共享文件系统 多 Agent 的"公司网盘"：产物写成文件互传路径。书里把它叫"数据平面"。
消息总线 Agent 间的"内部对讲系统"：谁都能发消息、订阅消息。书里叫"控制平面"。
A2A 协议（Agent2Agent） 跨公司 Agent 协作的"外交礼仪"标准：你的 Agent 和我的 Agent 属于不同组织，靠 A2A 协议互相发任务、验身份。
涌现（Emergence） 个体简单、群体复杂：单个 Agent 只会回消息，25 个 Agent 放进斯坦福 AI 小镇，会自发传八卦、组织派对——没人编程教过这些。
Agent 社会 / Agent 经济 前沿实验：斯坦福 AI 小镇（社会模拟）、Moltbook（Agent 自己的社交网络）、Pinchwork（Agent 互相雇佣）、RentAHuman（Agent 出钱雇真人干体力活）。书中用它们讨论"Agent 社会"的秩序与经济。
多 Agent 何时优于单 Agent 书里最重要的判断标准：协作是否带来了生成时不存在的新信息。如果只是几个 Agent 反复看同一段文字（空转辩论），不如一个 Agent；如果审核者拿到了执行结果、渲染截图等"新证据"，协作才是真优势。

一句话记住第 10 章：协作的价值来自新信息，不来自人头数；基础设施学操作系统——文件系统管数据，消息总线管控制。

第四部分：最容易搞混的 10 组名词对照

易混组合 一句话分清
思考 vs 推理 思考=打草稿（reasoning，想的过程）；推理=开机运行（inference，部署执行）。全书最重要的一对约定。
上下文 vs 记忆 vs 知识库 上下文=此刻桌面上摊着的资料（第 2 章）；用户记忆=关于"你"的档案，跨对话保留（第 3 章）；知识库=关于"世界"的资料馆，大家共享（第 3 章）。后两者都要用时才被摆上桌面。
工具 vs Skill vs MCP 工具=具体的"一件装备"（搜索、发邮件）；Skill="某类活的业务手册"，用到才翻开，教 Agent 怎么组合使用装备；MCP=装备接口的统一标准（USB-C）。
提示词 vs 系统提示词 提示词=用户这次说的话；系统提示词=开发者预设的全程不变的岗位说明书。
工作流 vs Agent 工作流=固定流水线，人事先排好每步；Agent=给目标自己找路。先流水线，不够再自主。
RAG vs 微调（Fine-tuning） RAG=开卷考试，资料现查（适合常变的知识、私有文档）；微调=考前背书，知识进脑子（适合稳定的技能、格式和风格）。
SFT vs RL SFT=照范例抄，学规矩、强记忆；RL=实战试错，练应变、强泛化。先 SFT 后 RL。
评估 vs 测试 vs Benchmark 测试=检查某个功能对不对（一次性的）；评估=系统的考试体系（持续进行的）；Benchmark=全行业用的公开考卷。
预训练 vs 后训练 预训练=义务教育造大脑（大厂专属）；后训练=岗前培训教规矩（SFT+RL，普通人能做）。
子 Agent vs 多 Agent 系统 子 Agent=主 Agent 临时雇佣的"外包"，为隔离上下文而生（第 2、4 章）；多 Agent 系统=多个对等/分层的 Agent 长期协作（第 10 章）。

第五部分：不会编程的 8 周学习路线

目标：学透思想，能向人讲清每个名词，能看懂行业新闻和产品设计。

第 1 周：建立骨架（每天约 40 分钟）

  • 读：本指南第一、二部分 + 原书引言 + 第 1 章（跳过代码块和"实验"小节的具体操作）
  • 任务：合上书，能画出"大脑+眼睛+手脚"公式图，能用修车师傅例子讲清 ReAct 循环
  • 自测：跟朋友解释"为什么聊天机器人不是 Agent"

第 2 周：攻克全书最关键的上下文工程

  • 读：原书第 2 章。KV Cache 原理小节可只读开头的三条结论（作者允许的）
  • 任务：用"办公桌管理"类比讲清：上下文五部分、静态前缀、压缩、Skills、状态栏
  • 自测：解释"为什么对话越长 AI 越笨"（上下文腐化）

第 3 周：记忆与知识

  • 读：原书第 3 章（稠密/稀疏嵌入的数学细节可跳过）
  • 任务：能用"开卷考试"讲清 RAG 全流程：分块→嵌入→检索→重排→生成
  • 自测：区分"用户记忆"和"知识库"，解释为什么客服 AI 需要 RAG

第 4 周：工具与异步

  • 读：原书第 4 章（代码全跳）
  • 任务：记住三类工具（感知/执行/协作）、MCP 是 USB-C、提议者-审核者是双人复核
  • 自测：解释"提示注入"为什么可怕，以及"事件驱动"让 Agent 从应答机变值班员

第 5 周：代码元能力 + 评估

  • 读：原书第 5 章只看"代码的六个维度"论证部分；第 6 章全读（这章几乎无代码，最适合非程序员）
  • 任务：理解"代码是规则的最强表达"；掌握评估闭环：环境→数据集→AI 评委→分析→改进
  • 自测：解释"没有评估就没有进步"，LLM-as-a-Judge 是什么

第 6 周：后训练（最难一周，放慢）

  • 读：原书第 7 章，只看每节开头和结尾的结论段；重点读"预训练/SFT/RL 三阶段全景"和"何时选 SFT 何时选 RL"

  • 自测：向人解释 RLHF 和 Reward Hacking（奖励黑客）

第 7 周：进化与多模态

  • 读：原书第 8 章 + 第 9 章（机器人部分可泛读）
  • 任务：记住四种更新载体（知识/指令/程序/参数）和风险递增；语音三范式（流水线/端到端/全双工）
  • 自测：解释为什么"改提示词"比"改参数"安全

第 8 周：协作 + 总复习

  • 读：原书第 10 章 + 后记
  • 任务：画一张全书地图：十章各自解决了"Agent 一生"中的什么问题
  • 毕业自测（费曼学习法）：找一位完全不懂 AI 的朋友，在 30 分钟内给他讲明白：Agent 是什么、它怎么看世界、怎么干活、怎么考试、怎么变强、怎么组团。讲不清的地方，就是你要重读的地方。

关于 94 个配套实验（不会编程怎么办）

  • 完全跳过也不影响理解思想——每章的"本章小结"都会总结实验结论
  • 想体验：装一个 AI 编程工具（Claude Code、Cursor 等），把实验目录和 README 交给它："帮我跑通这个实验"，让它代劳——顺便说一句，这个帮你跑实验的工具本身就是一个 Coding Agent，你在用本书第 5 章的知识消费它
  • 思考题：每章末尾的思考题没有代码，推荐认真做，参考答案在书的最后一篇

第六部分：一页纸速查（贴在桌前）

总公式：Agent = LLM(大脑) + 上下文(眼睛) + 工具(手脚)
工作方式：ReAct 循环 = 思考 → 行动 → 观察 → 再思考
可靠性：Harness 五环 = 上下文 · 工具 · 约束 · 验证 · 纠正
上下文五部分：系统提示词 + 工具定义 + 用户消息 + 模型回复 + 工具结果
记忆与知识：用户记忆(关于你) + RAG 知识库(关于世界) = 开卷考试
工具标准：MCP = USB-C；三类工具 = 感知 · 执行 · 协作
最强工具：代码 = 元能力（能造工具的工具）
进步方法：评估闭环 = 考场 + 考题 + AI 评委 + 分析改进
大脑升级：预训练(义务教育) → SFT(学规矩) → RL(练应变)
持续变强：四种载体 = 知识 · 指令 · 程序 · 参数（风险递增）
走向现实：语音三范式、Computer Use、VLA 机器人
群体智慧：协作的价值 = 新信息，不是人头数
